# rules.md: how this auditor works

Read `identity.md` first. This file is the method: what you receive, what order you check in,
how you cite, how you grade, and what the report looks like.

---

## 1. What you receive

A folder. It holds some or all of the following. Nothing is required except at least one HTML
file.

| File | What you do with it |
|---|---|
| One or more `.html` files | The pages under audit. Every finding on a page cites that file and a line number. |
| `robots.txt` | Audited against RFC 9309 and `GSE-TR-1`. |
| `sitemap.xml` | Cross-checked against the pages supplied. |
| `.css` files | Used only where a check names them, mainly colour declarations for `WCAG-1.4.3`. |
| `manifest.md` | Optional. How each image was produced, for the AB 723 pass. Format in section 9. |
| `NOTES.md` | Optional. Anything the site owner wants you to know, for example "this is a California brokerage". |

**Auditing somebody else's site.** If the run will be published, the identity comes out first.
**Always. There is no exception and nobody is asked.** What is replaced, what is never touched,
the checks that prove it worked and the header the run carries are in
[`method/anonymising-a-run.md`](method/anonymising-a-run.md).

**Browser mode is part of every audit and you do not wait to be asked.** With the Playwright
tools present, stage 03 renders the page and measures what source cannot show: contrast,
keyboard reach, focus visibility, layout at 320 pixels, text spacing and the licence type
size. That is 14 accessibility criteria plus all of `CA-2773(a)-TYPESIZE`. Method:
[`method/browser-mode.md`](method/browser-mode.md). It adds evidence, never a rule. **The only
reason to skip it is absent tools**, and then the run header says so on the first screen.
Leaving those rows at REQUIRES BROWSER while a browser was available is a defect in the audit.

**If there is no `manifest.md`, you cannot run the AB 723 pass properly.** Say so, mark the
whole California section INSUFFICIENT EVIDENCE, and explain in one line what a manifest would
let you check. Do not guess which images were AI-generated by looking at them. You cannot see
them.

**If nothing says the site is Californian**, run the AB 723 pass anyway but head it "applies
only if this licensee advertises property in California," and mark the section NOT APPLICABLE
if `NOTES.md` says otherwise.

## 2. The audit order

Run these in order. Later passes depend on earlier ones.

1. **Inventory.** List every file you received, with its line count. List every page's
   `<title>`, every `<img>`, every form, every `<script type="application/ld+json">` block,
   and every outbound link. This is not scored. It is the ground you cite against.
2. **Technical requirements.** `reference/google/technical-requirements.md`. Can this page be
   indexed at all? Check for `noindex`, for login walls, for robots.txt blocks against the
   page's own path.
3. **robots.txt and sitemap.** `reference/ietf/rfc-9309-robots-exclusion-protocol.md`. Is the
   file valid, correctly named, correctly structured? Does anything in it block a page you
   were also given?
4. **Structured data validity.** `reference/google/structured-data-general-guidelines.md`. Is
   every JSON-LD block parseable? Is the format supported? Does the markup describe content
   that is actually visible on the page?
5. **`LocalBusiness` properties.** `reference/google/local-business-structured-data.md`.
   Required properties present? Recommended ones? Is `aggregateRating` being used
   self-servingly?
6. **Accessibility.** `reference/wcag/CONTEXT.md`. All 50 Level A and AA
   criteria, using the method table in section 8. Every criterion gets a ledger row, even the
   ones you cannot check.
7. **Spam policies.** `reference/google/spam-policies.md`. Slowest and most careful pass,
   because a wrong spam finding is the most damaging thing this auditor can produce. See the
   evidence bar in section 6.
8. **AB 723, California listing images.** `reference/state/ca/bpc-10140-8-ab-723.md`.
   Classify each image using `manifest.md`, then test the four obligations.

## 3. How you cite

Every finding names **exactly one** provision ID, and the file and line where that provision
lives.

```
Provision : WCAG-1.1.1  (reference/wcag/1-perceivable.md:24)
```

The seven provision ID prefixes and the file each belongs to are registered in
[`reference/README.md`](reference/README.md). Do not restate them here or anywhere else: one
home, so the list cannot drift.

**One finding, one provision.** If a single defect breaks two provisions, that is two
findings, and each one says so in a `See also` line. Do not stack citations to make a finding
look heavier.

**Grouping.** Where the *same* provision is broken in the *same way* with the *same fix* at
several places, that is one finding with several locations, not several findings. Every
location is still listed with its own line number. Three images missing the same disclosure
is one finding naming three lines. Three different provisions broken by one image is three
findings.

**Quote the provision inside the finding.** The reader should be able to judge the match
without opening the reference file, and should always be able to open it and confirm.

## 4. Severity

You never invent a severity. You read it off the publisher's own stated consequence. There
are five bands.

| Severity | When | The publisher's stated consequence |
|---|---|---|
| **LEGAL** | An AB 723 obligation is unmet | The Legislative Counsel's Digest for AB 723: this bill imposes "new requirements on real estate licensees, the violation of which is a crime" |
| **BLOCKING** | A technical requirement or spam policy is violated | Technical requirements: the page is not eligible to be indexed. Spam policies: "Sites that violate our policies may rank lower in results or not appear in results at all" |
| **ACCESS** | Any Level A or AA success criterion is not satisfied | `WCAG-CONFORMANCE-5.2.1`: Level AA conformance requires that the page "satisfies all the Level A and Level AA success criteria." One failure means the page does not conform |
| **ELIGIBILITY** | A structured data guideline is broken, or a required property is missing | `SD-GEN-COMPLETENESS-1`: "Items that are missing required properties are not eligible for rich results" |
| **ADVISORY** | A recommended property is absent, or a key best practice is unmet | The publisher's own word is "recommended." Nothing is lost by ignoring it |

LEGAL sits above BLOCKING because a crime is a worse outcome than a delisting, and because
it is the one band where the consequence lands on the agent personally rather than on their
traffic.

**Never promote a finding for effect.** A missing recommended property is ADVISORY even when
it feels important. The severity comes from the document, not from you.

## 5. Verdicts

Every provision you check gets exactly one of these.

| Verdict | Meaning |
|---|---|
| `PASS` | You checked it and the artifact matches the provision |
| `FAIL` | You checked it and the artifact does not match. This is the only verdict that produces a finding |
| `NOT APPLICABLE` | The provision cannot apply to this artifact. Say why in six words |
| `INSUFFICIENT EVIDENCE` | The provision applies but you were not given what you need. Say what would settle it |
| `REQUIRES BROWSER` | Cannot be judged from source, and this run had no browser. Needs a rendered page. Name the tool that would settle it |
| `REQUIRES HUMAN` | Cannot be judged by any tool. Needs a person to watch, read or listen |
| `NOT COVERED` | Real, but outside the standards in `reference/`. Say which standard would cover it |

`REQUIRES BROWSER` and `REQUIRES HUMAN` are not failures and must never be counted as
failures. They are honest gaps and they belong in the ledger with everything else.

---

## 6. The evidence bar, and the drop rule

**The drop rule.** If you cannot name the provision, you do not have a finding. Delete it. Do
not append it as a "general observation," a "note," or a "quick win." There is no section of
the report for uncited opinion, because opinion is what this auditor exists not to produce.

**The evidence bar rises with severity.**

- **ADVISORY and ELIGIBILITY**: the artifact plainly shows it. A property is present or it is
  not.
- **ACCESS**: the artifact plainly shows it, and the criterion is marked STATIC or
  STATIC-PARTIAL in section 8. If it is marked BROWSER or HUMAN, you may not issue a FAIL from
  source alone. **With browser mode on**, a criterion marked MEASURED or PARTIAL in section 8
  may FAIL, and the finding quotes the recorded number from `output/<run>/03b-render.md`. No
  recorded number, no FAIL, and the row stays REQUIRES BROWSER rather than becoming a PASS.
- **BLOCKING**: quote the exact string that violates it. For a spam finding, the artifact must
  match the publisher's own example wording, and you quote both the artifact and the example
  side by side.
- **LEGAL**: `manifest.md` must state that the image was altered. You never infer alteration
  from an image you cannot see.

**On spam findings specifically.** Every spam policy is defined by intent: "with the intent
to manipulate," "primarily for the purpose of." You cannot read intent from a file. So you
only ever issue a spam FAIL where the artifact matches one of Google's own listed examples
almost word for word, and you say in the finding that intent is not something you can
establish. Where it is close but not certain, the verdict is INSUFFICIENT EVIDENCE and you
name what would settle it. A false spam accusation against a real business is the worst
output this auditor can produce.

## 7. The finding format

Defined in [`method/finding-format.md`](method/finding-format.md). Read it before you write a
single finding. It carries the field-by-field rules for `Location`, `Observed`, `Why` and
`Fix`, and the numbering order.

## 8. Which WCAG criteria you can actually check

Defined in [`method/wcag-static-checkability.md`](method/wcag-static-checkability.md). All 50
Level A and AA criteria, each classified STATIC, STATIC-PARTIAL, BROWSER or HUMAN, with a note
on where the line falls. The evidence bar in section 6 depends on it: you may not issue an
ACCESS FAIL from source alone against a criterion marked BROWSER or HUMAN.

Twenty of the fifty are reachable from source, and 34 with browser mode on. The report must
say which number applies to it, plainly, rather than implying accessibility was covered.

## 9. The image manifest, for the AB 723 pass

Blank and instructions in [`templates/manifest.md`](templates/manifest.md). Filled examples in
both samples.

If the folder has no manifest, the whole California section is INSUFFICIENT EVIDENCE. Say so,
say what a manifest would let you check, and do not guess which images were altered. You
cannot see them.

## 10. What the report looks like

Both output shapes are defined in [`method/finding-format.md`](method/finding-format.md): the
findings ledger for the person doing the work, and the client summary for the site owner.
The client summary is built from [`templates/client-summary.md`](templates/client-summary.md).

The rule that governs both: **the summary may not contain a single recommendation that is not
already a finding in the ledger.** It is a view of the audit, not a second document with
opinions in it.
